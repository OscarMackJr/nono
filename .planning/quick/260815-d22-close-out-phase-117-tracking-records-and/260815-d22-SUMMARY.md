### [Rule 3 - Blocking] Both of the plan's automated verification gates were themselves defective

Neither defect was a mismatch between the plan and the tree. In both cases the *edits* were correct
and the *gate* could not report so. I corrected the gates and recorded the proof rather than
adjusting the record to fit.

**1. Task 1's line-count predicate under-counted removals.** The gate used
`grep -cE '^-[^-]'` and reported 3 (expected 6) for REQUIREMENTS and 1 (expected 2) for ROADMAP.
Cause: markdown checklist lines *begin with `-`*, so a removed `- [ ] **CINT-01**` renders in the
diff as `-- [ ] **CINT-01**`; `[^-]` then rejects it. Additions were unaffected because `+- [x]`
has a non-`+` second character — which is exactly why the counts were asymmetric. `git diff --numstat`
confirms the true counts are 6/6 and 2/2 as the plan intended. Re-ran the gate with `--numstat` as
the counter; `TASK1_VERIFIED`. My replacement negative-grep for v3.5/TSBX/DRAIN/RCPT/BOUND content
is also strictly stronger than the plan's, since it inspects all 20 changed lines including the
`--`-prefixed ones the original silently skipped.

**2. Task 2's ci.yml semantic-equality check compared two different decodings.** The gate read the
working tree with `open(..., encoding='utf-8')` but read the git blob with
`subprocess.run(..., text=True)`, which decodes using the Windows locale codepage. `ci.yml` contains
em dashes, so the two sides could never compare equal on this host. Proved decisively rather than
assumed: with the ci.yml blob **byte-identical** between `HEAD~1` and `HEAD`, the gate's own two
decode paths still disagreed (`yaml(locale) == yaml(utf8)` → `False`). Re-ran decoding both sides as
UTF-8; `CI_YAML_PARSES_AND_IS_SEMANTICALLY_IDENTICAL`.
