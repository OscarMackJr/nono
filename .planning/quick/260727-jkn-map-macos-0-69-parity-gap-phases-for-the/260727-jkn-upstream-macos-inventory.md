## 1. tool-sandbox subsystem (v0.65.0 PR #1105)

**What it is.** A per-tool-call / per-command confinement layer that sits *inside* an
already-sandboxed agent session. When an AI agent (running under `nono run`) invokes an
external command (e.g. `git`, `gh`, `gk`, a package manager), that command is not run
directly — it is intercepted by a **shim**, brokered to the unsandboxed supervisor, and
re-launched under its own tight per-command sandbox profile with its own filesystem grants,
network policy, credentials, and stdio limits. This is the "sandbox the tools" model:
policy is expressed per-command in the profile's `command_policies`, and each mediated
invocation gets a fresh, minimal capability set rather than inheriting the agent's broad one.

The runtime module lives at `crates/nono-cli/src/tool-sandbox/` and is compiled
**only for `target_os = "linux"` or `"macos"`** (`mod.rs` stubs out everything else with a
no-op `PreparedToolSandboxRuntime`). This is the single largest gap for Windows parity: the
entire subsystem has **no Windows implementation** — there is no `platform/windows.rs`.

**Architecture / mechanism.**
- **Private shim materialisation.** For each controlled command, nono materialises a copy of
  the `nono` binary under a private shim dir (`NONO_TOOL_SANDBOX_SHIM_DIR`) named as the
  command. The agent's sandbox `process-exec` allowlist only permits execs from that shim
  dir, so any tool call is forced through nono. A reserved `open` shim (`url_shim.rs`)
  intercepts browser-opens.
- **Shim IPC over a Unix domain socket.** The shim connects back to the supervisor's
  listener (`NONO_TOOL_SANDBOX_SOCKET`), sends a `ToolSandboxShimRequest` (command + argv +
  cwd), and passes the child's **stdio file descriptors via `SCM_RIGHTS`** ancillary data
  (`protocol.rs`: `send_fd_via_socket`/`recv_fd_via_socket`, `recv_stdio_fds`). The
  supervisor authenticates the peer by PID (`SO_PEERCRED` on Linux; `proc_pidinfo` /
  `proc_pidpath` FFI on macOS) and resolves which command the caller "is".
- **Brokered launch under fresh sandbox.** The supervisor writes a
  `ToolSandboxChildLaunchSpec` (real binary path + hash, argv, filtered env, `ChildCapsSpec`,
  cwd, stdio) to a spec file, then re-execs `nono` as an internal **child launcher**
  (`launch.rs` / `run_child_launcher`) which: chdir's, re-verifies the binary
  (`verify_launch_binary`), builds a `CapabilitySet` from the spec, calls `Sandbox::apply_auto`,
  then `execve`'s the real tool. So the per-command Seatbelt/Landlock profile is generated by
  the **core library** from the spec's caps, not hand-rolled in the tool-sandbox module.
- **Dynamic token expansion** (`dynamic_providers.rs`, 1263 lines). Profile path lists may
  contain `@<provider>:<query>` sentinels (e.g. `@git:config-files`, `@git:common-dir`,
  `@git:worktree`) expanded at launch into concrete per-user paths (parsed from
  `git config --list --show-origin --show-scope`, run from the repo root). Lets a shipped
  profile cover user-specific dotfiles without enumerating them.
- **Credential / token brokering** (`token_broker.rs`, `credentials.rs`). Real credential
  values never enter the agent's address space: they are replaced with `nono_<64hex>` nonces.
  Nonces are **capability-bound** (`GrantSet`) — redeemable only by a named consumer
  (`cmd.<name>` env-promotion path or `proxy.<route_id>` L7 header-injection path). The broker
  resolves the nonce to the real value immediately before `execve` (env promotion) and
  `scan_and_reissue` redacts any leaked nonce/value from captured stdout. All values zeroed on
  drop (`zeroize`). Credential kinds: `LocalSocket`, `RawFile`, `Proxy`, `Ambient`.
- **URL shim** (`url_shim.rs`). A brokered child under a tight `process-exec` allowlist cannot
  exec `/usr/bin/open` / `xdg-open` for OAuth logins, so it execs the reserved `open` shim,
  which connects to a dedicated URL listener socket (`NONO_TOOL_SANDBOX_URL_SOCKET`) and asks
  the unsandboxed runtime to validate (per-command `open_urls` origin allowlist) and open it.
- **Intercept actions** (`policy.rs`). Per-command `intercept` rules match argv and choose an
  action: `Passthrough`, `Capture` (return stdout to agent, redacted), `Deny`, and (v0.67.0
  #1322) `Exec`. Per-intercept and per-command sandbox overrides are supported.

**macOS-specific details (`platform/macos.rs`).**
- **`proc_pidinfo` / `proc_pidpath` FFI** (`PROC_PIDTBSDINFO`, `ProcBsdInfo`) is the macOS
  substitute for Linux `/proc` ancestry — used to walk the caller's process ancestry, resolve
  which command a shim connection belongs to, and (v0.69.0 #1417) verify a **daemonized caller**
  (`setsid`+double-fork, reparented to pid 1) against a command's declared `daemon_pid_source`
  helper, pinned by kernel identity so a recycled pid can't inherit a stale allow/deny.
- **SCM_RIGHTS EMSGSIZE quirk** (#1325, v0.67.0). On macOS, `sendmsg` with SCM_RIGHTS
  ancillary data returns `EMSGSIZE` if the peer's receive buffer still holds unread frame
  bytes. Fix: the supervisor **acks the request frame before** receiving the stdio fds, proving
  the buffer is drained so the shim's fd-passing `sendmsg` can queue atomically
  (`handle_shim_stream_inner`, ~line 942).
- **No fexecve/execveat on macOS** → the child launcher can hash the binary but the final exec
  is path-based; `verify_launch_binary` re-verifies against the recorded hash before
  `Sandbox::apply_auto` + path `execve`. argv[0] is preserved for symlink-dispatched commands
  (#1413) without widening trust (argv[0] is a string; `real_binary` selects what runs).
- **HOME forwarding to the launcher** (`launch.rs`). The launcher re-exec runs `env_clear()` but
  **must forward HOME**, because the library's macOS profile generation reads HOME to recognise
  user keychain DBs (`$HOME/Library/Keychains/{login,metadata}.keychain-db`) and decide whether
  to drop the securityd/secd/keychaind mach-lookup denies. Clearing HOME would block keychain
  access even when the DB files are granted — a macOS-only Seatbelt/Mach-IPC subtlety.
- **`unsafe_macos_seatbelt_rules` escape hatch** (v0.67.0). Per-command raw Seatbelt rule
  injection, but untrusted rules nested in command/intercept sandboxes are **stripped before
  emission** and warned on (#1333-adjacent hardening commits).

**The 12 files (roles).**

| File | Role |
|------|------|
| `mod.rs` | Module root + non-unix no-op stubs; `ToolSandboxPrepare` spec; `admit_command_cwd` / `lexically_normalize` (a mediated command may only run where the agent itself is granted; write non-escalation). |
| `protocol.rs` | Wire protocol: socket env-var names, `ToolSandboxShimRequest/Response`, `ChildCapsSpec`, `StdioFds`, launch spec, SCM_RIGHTS fd send/recv, frame ack, URL-open request/response + IO timeout. |
| `launch.rs` | Builds the re-exec child-launcher `Command` (`env_clear`, forward HOME/RUST_LOG), writes/removes the launch-spec file, exit-status helper. |
| `policy.rs` | Intercept-action resolver: matches argv against `intercept` rules → `ResolvedInterceptAction` (Passthrough/Capture/Deny/Exec) with per-rule sandbox overrides. |
| `token_broker.rs` | Nonce credential broker (`nono_<64hex>`), capability-bound `GrantSet`, `resolve_env_entry`, `scan_and_reissue` redaction, zeroize-on-drop; `SharedBroker` shared with proxy. |
| `credentials.rs` | Resolves per-command `credentials` into `ResolvedCredential` (LocalSocket / RawFile / Proxy / Ambient); local-socket path templating. |
| `dynamic_providers.rs` | `@<provider>:<query>` token expansion; the `git` provider parses git config for per-user config/worktree/common-dir paths. |
| `env.rs` | Default env allowlist (PATH/HOME/proxy vars/TLS trust-bundle vars), `allow_vars` filtering, shebang interpreter resolution, URL-open/chaining env injection, argv[0] handling. |
| `url_shim.rs` | Child-side `open` shim: detects it was invoked as the reserved shim, connects to URL socket, requests browser-open from the unsandboxed runtime. |
| `audit_context.rs` | `ToolSandboxAuditContext` — profile display name + `ScrubPolicy` redaction policy for audit records. |
| `platform/macos.rs` | macOS runtime: `proc_pidinfo`/`proc_pidpath` ancestry + daemon-pid lineage, shim listener, SCM_RIGHTS handshake (EMSGSIZE ack ordering), child launcher → `Sandbox::apply_auto` + path `execve`. |
| `platform/linux.rs` | Linux runtime: `SO_PEERCRED` auth, `/proc` ancestry, `lineage_cgroup` daemon attribution, Landlock caps, `execveat`/`fexecve` binary-pinned exec. |

## 3. Platform-mechanism-specific items (need a distinct Windows mechanism for parity)

Each of these is implemented against a Unix primitive with no direct Windows analog. For
Windows parity the maintainer must supply the named substitute.

| Item (PR/ver) | Unix mechanism | Windows equivalent needed |
|---------------|----------------|---------------------------|
| tool-sandbox stdio hand-off (#1105) | **`SCM_RIGHTS` fd passing over `AF_UNIX`** (`sendmsg`/`recvmsg` ancillary data; macOS EMSGSIZE ack-ordering quirk #1325) | Handle duplication (`DuplicateHandle` + named-pipe / ALPC), or pass stdio via `STARTUPINFO`/`PROC_THREAD_ATTRIBUTE_HANDLE_LIST` to the brokered child |
| Shim caller authentication (#1105) | Linux `SO_PEERCRED`; macOS `proc_pidinfo`/`proc_pidpath` PID ancestry walk | Named-pipe `GetNamedPipeClientProcessId` + `OpenProcess`/token check; ancestry via `NtQueryInformationProcess`/toolhelp |
| Daemonized-caller attribution (#1417) | Linux cgroup lineage marker; macOS reparent-to-pid-1 + `daemon_pid_source` verified via `proc_pidinfo` kernel identity | Job Object membership / process-creation-time identity pinning |
| `--max-processes` (#1403) | **cgroup v2 `pids.max`** | **Job Object `JOBOBJECT_BASIC_LIMIT_INFORMATION.ActiveProcessLimit`** |
| `--memory` (#1269) | cgroup v2 `memory.max` (kernel OOM-kill) | Job Object `JOBOBJECT_EXTENDED_LIMIT_INFORMATION` `ProcessMemoryLimit` / `JobMemoryLimit` |
| `MAX_CRYPTO_THREADS`=12 (#1424) | macOS **libdispatch workqueue** thread accounting in exec-strategy threading gate | N/A on Windows (thread-count gate is tuned to the Seatbelt/libdispatch threat model; verify the Windows threading context does not trip the same gate) |
| Per-command re-exec + sandbox (#1105) | Linux `execveat`/`fexecve` binary-pinned exec; macOS path-based `execve` + pre-exec hash re-verify | `CreateProcess` has no fexecve; pin via signed-image/hash re-verify before launch (fork already does broker-launch binary trust gating) |
| Seatbelt raw-rule escape hatch (`unsafe_macos_seatbelt_rules`) | Seatbelt SBPL string injection | No parity target — macOS-only DSL |
| Port ranges (#1398) | Seatbelt per-port `remote tcp "localhost:N"` rule expansion (17,770 cap) | WFP filter conditions on remote port ranges (WFP can express ranges natively — likely *simpler* than Seatbelt's per-port expansion) |

## 4. macos.rs core Seatbelt driver — diff summary (v0.64.0 → v0.69.0)

Only one functional change landed in `crates/nono/src/sandbox/macos.rs` across the window:
**port-range support (#1398, v0.68.0).**

- New imports from `capability`: `MACOS_PORT_RANGE_LIMIT`, `merge_port_ranges`.
- `push_localhost_tcp_outbound_seatbelt_rules` gained a `localhost_port_ranges: &[(u16,u16)]`
  parameter. Each range is **expanded to one `(allow network-outbound (remote tcp
  "localhost:N"))` rule per port** — Seatbelt cannot express a port range, so it is unrolled.
- `generate_profile` now calls `merge_port_ranges(caps.localhost_port_ranges())`, sums the
  unique ports, and **hard-errors** (`NonoError::SandboxInit`) if the total exceeds
  `MACOS_PORT_RANGE_LIMIT` — because `sandbox_init` crashes above ~17,770 rules. This is a
  fail-secure guard, not silent truncation.
- A `has_localhost_tcp` flag (`!localhost_ports.is_empty() || !merged_ranges.is_empty()`) now
  gates the AF_INET/AF_INET6 `system-socket` allows and the blanket `network-bind`/
  `network-inbound` allows across the `Blocked`, proxy-only, and default paths (Seatbelt still
  cannot filter bind/inbound by port — blanket allow when any localhost TCP is permitted).
- Range expansion is wired into all three network modes (blocked, proxy-only, default).
- The `debug!` of the full generated profile was reduced to `("Generated Seatbelt profile
  ({} bytes)")` to avoid dumping the (now potentially huge) profile text.
- Six new unit tests cover small-range expansion, under-limit expansion, over-limit error,
  cumulative-over-limit error, multiple ranges, and range-in-proxy-only mode.

No other edits to the core Seatbelt driver in this window — everything else macOS-relevant is
in the CLI (`tool-sandbox/platform/macos.rs`, `exec_strategy.rs`) or the profile/policy layer.
