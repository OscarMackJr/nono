# Quick Task 260906-q7n

## The defect: a redirection guard that fails open under elevation

`windows-layer-fault-injection` failed
`receipt_sink::tests::validate_and_join_sink_base_rejects_a_user_owned_redirection`:

```
a user-owned base must be rejected as a redirection signal:
  "C:\Users\RUNNER~1\AppData\Local\Temp\.tmpeQ6bkt\nono\receipts"
```

The message carries a **returned path**, so `validate_and_join_sink_base`
returned `Ok`, not `Err`. A `tempdir()` standing in for a hostile
`%PROGRAMDATA%` redirect was **accepted**. This is a confirmed fail-open, not a
flaky assertion.

## Why the reviewed rationale was wrong

The guard's only test was `path_is_owned_by_current_user`, with this documented,
review-sanctioned rationale (`receipt_sink.rs`, pre-change):

> A directory the CURRENT user owns is, by definition, one that user (or any
> process running as them) could have created themselves — exactly the
> redirection this check exists to catch.

The unstated premise is **"a redirection target will be current-user-owned."**
That is false under elevation. `path_is_owned_by_current_user` compares the
object owner SID against the token **USER** SID via `EqualSid`; on an elevated
process the default owner of newly created objects is `BUILTIN\Administrators`.
So a redirect created by an elevated process is *not* current-user-owned and
passes.

The predicate therefore covered only the **non-elevated subset** of the class it
claimed to cover — the project's recorded "predicate width, not just placement"
lesson, recurring. This is the same mechanism `260815-gfd` found (cluster A),
surfacing at a new call site; there it failed *safe*, here it fails *open*.

The original review explicitly considered `SHGetKnownFolderPath` and deferred it
as "a future hardening step". Operator chose to take that step now.

## Fix

Three layers, in `crates/nono/src/sandbox/windows.rs`, `crates/nono/src/lib.rs`,
and `crates/nono-cli/src/receipt_sink.rs`:

1. **New core primitive `known_folder_program_data()`** —
   `SHGetKnownFolderPath(FOLDERID_ProgramData)`. `%PROGRAMDATA%` is an ordinary
   environment variable and therefore attacker-controlled input; the
   known-folder table is registry-backed and not user-writable. `KF_FLAG_DEFAULT`
   + null `htoken` (resolve, do not create). Fail-closed: never falls back to the
   environment. COM allocation freed via an RAII guard on every exit path,
   including error paths.
   - ADR-86 boundary: this is an OS primitive, not policy — the same category as
     the neighbouring `path_is_owned_by_current_user`. Core is the right home.
2. **`validate_and_join_sink_base` primary check** — the candidate must *be* the
   OS-resolved root, compared via `same_existing_dir`, which canonicalizes both
   sides. Canonicalization is required, not cosmetic: CLAUDE.md forbids string
   operations on paths, and the CI runner surfaces 8.3 short names
   (`C:\Users\RUNNER~1\...`) that a byte comparison would mis-handle. Fail-closed
   on any canonicalize error.
3. **Ownership check retained as defense in depth**, demoted to secondary, with
   a comment stating exactly why it cannot be primary.

Also added a **scope-limit note on `path_is_owned_by_current_user` itself**, so
the next caller is warned at the definition rather than discovering it in CI:
it is a sound `WRITE_OWNER` proxy on non-elevated accounts (its original and
intended use) and is *not* a general "did a user create this" test.

## Verification

1. All 16 `receipt_sink::` tests pass (non-zero count asserted).
2. **New positive test** `accepts_the_os_resolved_root` — without it, a guard
   that rejected everything unconditionally would satisfy every other test in the
   module; the rejection tests alone cannot distinguish "correctly
   discriminating" from "broken shut".
3. **New elevation-independent test** `rejects_a_system_owned_non_root`, using
   `C:\Windows`: it is not current-user-owned, so the OLD predicate would have
   **accepted** it. This reproduces the CI fail-open on a non-elevated host, with
   an explicit precondition assert so it cannot silently become vacuous.
4. **Perturbation proof:** forcing `same_existing_dir` to return `Ok(true)` must
   fail `rejects_a_system_owned_non_root`.
   - Expected and observed nuance: `rejects_a_redirection` still **passes** under
     that perturbation, because on this non-elevated host the tempdir *is*
     current-user-owned and the secondary check catches it. That is precisely why
     Phase 118 never caught this locally, and it is why test 3 exists.
5. `cargo fmt --all --check` clean; `clippy -D warnings -D clippy::unwrap_used`
   exit 0 on both changed crates.
6. **Both mandatory cross-target gates** — `lib.rs` carries
   `#[cfg(target_os = "linux")]` blocks, so CLAUDE.md's rule is triggered.

## Scope guard

- The `windows-sys` feature additions (`Win32_UI_Shell`, `Win32_System_Com`) go
  in the existing `[target.'cfg(target_os = "windows")'.dependencies]` table —
  verified target-scoped, so non-Windows targets are structurally unaffected.
- The new re-export sits inside the existing `#[cfg(target_os = "windows")]`
  block in `lib.rs`.
- No change to D-08's write-integrity-only scope, to the receipt schema, or to
  the chain. This is the resolution of `%PROGRAMDATA%` only.
