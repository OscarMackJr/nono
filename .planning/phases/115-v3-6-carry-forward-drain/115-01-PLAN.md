<objective>
Close DRAIN-01 (NEW-05 + ACC-04): change `CustomCredentialDef.inject_mode`/`inject_header` from
serde-defaulted non-Option fields to `Option<T>`, resolved at the use site, so a
`platform_overrides.<os>` block that redefines a credential and omits these two fields inherits
the base's values instead of silently resetting a `url_path`/`query_param` route to header-mode
`Authorization`. Extend the NEW-02 regression test to assert every merged field exhaustively
(closing ACC-04's missing `spiffe` assertion), and add a compile-time guard on `HookConfig` so a
future field addition there cannot silently reopen the same class of bug.

Purpose: a credential-placement bug (where on the wire a credential lands) must be structurally
unrepresentable, not merely caught by a hand-written test — per this phase's governing rule.
Output: `CustomCredentialDef` with homogeneous `Option<T>` optional fields, a corrected doc
comment (D-05), an exhaustive regression test, and a compile-time guard on `HookConfig` (D-04)
with a verified bite-proof artifact.
</objective>
