<objective>
Close DRAIN-06 (NEW-08): reorder the SPIFFE route dispatch path in `reverse.rs` so the
`deny_domain` filter host-check runs before `managed_auth.acquire()` (the SPIRE Workload API
fetch), matching the check-first structure every other dispatch path in this file already uses.
Today, a `deny_domain`-blocked SPIFFE upstream still triggers a live SPIRE fetch before being
denied — no leak (the token never reaches the wire), but a needless external call and an ordering
inversion relative to every sibling path.

**Test-mechanism decision (made here, per VALIDATION.md's requirement, not left to the
executor):** the regression test uses the structural option — proving the deny returns before
`managed_auth.acquire()` is reachable — rather than a test double or a live-SPIRE-socket
integration test. Rationale: it matches D-17's own hoist mechanism, needs no SPIRE agent, and is
consistent with this phase's "unrepresentable over tested-for" through-line; the other two options
were rejected as either requiring a new production test-seam (test double) or being partially
host-gated (live-socket test) for no additional proof strength.

Purpose: fail-secure ordering — deny before any external attestation call, not after.
Output: reordered dispatch in `reverse.rs`, plus a load-bearing structural regression test in
`spiffe_integration.rs`.
</objective>
