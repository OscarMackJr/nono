<objective>
Close DRAIN-04 (NEW-03): reject any profile declaring `aws_auth` (D-13) or plain OAuth2
`client_credentials` with no `client_assertion` (D-14) at config-validation time, rather than
accepting the config and having it fail (or, worse, silently no-op) at request time. Both
mechanisms are config surfaces with no working implementation — `aws_auth` unconditionally 501s
at `reverse.rs:328-331`, and plain `client_credentials` (RESEARCH Q2, confirmed by source trace)
inserts into none of `CredentialStore`'s maps and forwards the request to upstream with **zero
token injection** — a fail-open strictly worse than a 501.

Purpose: fail-secure means reject at load time when a mechanism cannot work, not discover it at
request time (or never discover it, in D-14's silently-degraded case).
Output: two new validation rejections in `profile/mod.rs`, updated schema descriptions, updated
existing tests (the intended breakage), and a divergence-ledger carry-forward note.
</objective>

`validate_custom_credential`'s existing mutual-exclusion idiom (`profile/mod.rs:1146-1154`):
```rust
fn validate_custom_credential(name: &str, cred: &CustomCredentialDef) -> Result<()> {
    if cred.aws_auth.is_some() && (cred.credential_key.is_some() || cred.auth.is_some()) {
        return Err(NonoError::ProfileParse(format!(
            "custom credential '{}' has 'aws_auth' set together with 'credential_key' or 'auth'; \
             aws_auth is mutually exclusive with both — remove the other auth field",
            name
        )));
    }
```
D-13 makes `aws_auth.is_some()` alone (regardless of what else is set) a rejection.

The 501 guard this supersedes (`crates/nono-proxy/src/reverse.rs:323-331`):
```rust
// AWS SigV4 signing is not yet implemented. Return 501 so the caller
// knows the route exists but is not functional. ...
if aws_route.is_some() {
    send_error(stream, 501, "Not Implemented").await?;
    return Ok(());
}
```

`validate_oauth2_auth` (`profile/mod.rs:1302-1364`, current shape):
```rust
fn validate_oauth2_auth(name: &str, auth: &OAuth2Config) -> Result<()> {
    validate_upstream_url(&auth.token_url, &format!("{}/auth.token_url", name))?;

    if let Some(ref assertion) = auth.client_assertion {
        match assertion {
            nono_proxy::config::ClientAssertionConfig::SpiffeJwt { workload_api_socket, audience, .. } => {
                if workload_api_socket.is_empty() { return Err(NonoError::ProfileParse(...)); }
                if audience.is_empty() { return Err(NonoError::ProfileParse(...)); }
            }
        }
        return Ok(());   // <- D-14 rejection inserts immediately after this, before the checks below
    }

    if auth.client_id.is_empty() {
        return Err(NonoError::ProfileParse(format!(
            "auth.client_id for custom credential '{}' cannot be empty",
            name
        )));
    }
    ...
```
RESEARCH Q2 trace (unwired, confirmed): `credential.rs:296-384`'s `oauth2` branch only handles
`Some(ClientAssertionConfig::SpiffeJwt {...})` via `if let`; plain `client_credentials`
(`client_assertion: None`) falls through the whole block as a no-op — the route is inserted into
none of `credentials`/`aws_routes`/`spiffe_assertion_routes`. Dispatch
(`reverse.rs:250`, `ctx.credential_store.get(&service)`) returns `None`, so the request proceeds
to upstream via the "no-credential route (L7 filtering only)" branch (`:293-299`) with **zero
token injection**.

separate executor passes.
