fn validate_header_name(cred_name: &str, header: &str) -> Result<()> {
    if header.is_empty() {
        return Err(NonoError::ProfileParse(format!(
            "inject_header for custom credential '{}' cannot be empty", cred_name
        )));
    }
    if !header.chars().all(is_http_token_char) {
        return Err(NonoError::ProfileParse(format!(
            "inject_header '{}' for custom credential '{}' contains invalid characters; \
             header names must be valid HTTP tokens (alphanumeric and !#$%&'*+-.^_`|~)",
            header, cred_name
        )));
    }
    Ok(())
}

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Profile JSON (operator-authored, potentially untrusted if profiles are shared) <-> parsed CustomCredentialDef/RouteConfig | Schema + validate_custom_credential() are the enforcement point; a malformed or under-specified spiffe block must be rejected at load time, not silently accepted with empty fields. |
| Sandboxed child <-> SPIRE Workload API Unix socket | enforce_spiffe_socket_isolation() is the sole mitigation preventing the child from self-issuing SVIDs by reaching the agent socket directly. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-113-04 | Spoofing / Elevation of Privilege | Sandboxed child reaching the SPIRE Workload API socket directly | mitigate | `enforce_spiffe_socket_isolation()` — deny-by-omission (no `unix_socket` grant ever issued for the path) on Linux/macOS, hard error on a conflicting explicit grant. |
| T-113-05 | Elevation of Privilege | Windows AppContainer socket isolation for SPIRE sockets | accept (named residual risk, per 113-RESEARCH.md's Security Domain note) | Windows Unix-domain-socket paths are not independently verified this phase to be default-denied by AppContainer for unlisted sockets; consistent with the fork's existing Windows sandbox model but flagged, not silently assumed safe. Confirmed or closed in Plan 113-08's final verification pass, not here. |
| T-113-06 | Tampering | A profile with `client_id`/`client_secret` BOTH empty and no `client_assertion` | mitigate | `validate_oauth2_auth`'s else-branch still rejects empty `client_id`/`client_secret` when `client_assertion` is absent — the `#[serde(default)]` relaxation only permits omission when the assertion alternative is present, never a silent no-auth OAuth2 route. |
| T-113-07 | Information Disclosure | `nono-profile.schema.json`'s `additionalProperties: false` posture | accept | Preserved on every new `$defs` block per the existing fork convention — an unrecognized SPIFFE sub-field is a hard schema-validation rejection, not a silently-ignored typo. |
