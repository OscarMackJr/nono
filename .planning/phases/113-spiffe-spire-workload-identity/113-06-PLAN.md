pub async fn handle_reverse_proxy(
    first_line: &str, stream: &mut TcpStream, remaining_header: &[u8],
    ctx: &ReverseProxyCtx<'_>, buffered_body: &[u8],
) -> Result<()> {
    let (method, path, version) = parse_request_line(first_line)?;
    let (service, upstream_path) = parse_service_prefix(&path)?;
    let route = ctx.route_store.get(&service).ok_or_else(|| ProxyError::UnknownService { prefix: service.clone() })?;
    // ... existing endpoint_rules / endpoint_policy checks, unchanged ...

    // NEW dispatch point, inserted where the existing code branches on
    // `ctx.credential_store.get(&service)` (static credential) today:
    if route.has_spiffe_source() {
        return handle_spiffe_route(first_line, stream, remaining_header, ctx, buffered_body, &service, &upstream_path, route).await;
    }
    if let Some(spiffe_assertion) = ctx.credential_store.get_spiffe_assertion(&service) {
        return handle_spiffe_assertion_credential(first_line, stream, remaining_header, ctx, buffered_body, &service, &upstream_path, spiffe_assertion).await;
    }
    // ... existing static_cred / no-credential branches, UNCHANGED ...
}

`handle_spiffe_route`'s body (new fn, same file) mirrors the existing static_cred flow step-by-step

```rust
async fn handle_spiffe_route(/* ... */) -> Result<()> {
    // 1. Auth gate — IDENTICAL to the existing static_cred branch: gated on ctx.require_auth,
    //    calls validate_reverse_local_auth (D-01's evidence text: this piece ports cleanly
    //    standalone). On failure: audit::log_denied + 401/407 + return, exactly as today.

    // 2. Acquire the credential (THIS is the new step, replacing a keystore lookup):
    let managed_auth = route.managed_auth.as_ref().expect("has_spiffe_source() implies managed_auth is Some");
    let material = managed_auth.acquire().await.map_err(|e| {
        // fail closed: 503, audit denied — this is D-03's "credential acquisition fails at
        // request time" case, distinct from D-04's load-time fail-closed case.
        e
    })?; // on Err: audit::log_denied with denial_category ManagedCredentialUnavailable, send 503, return Ok(())

    // 3. Build + parse + filter + connect upstream — VERBATIM reuse of the existing
    //    parse_upstream_url() / filter.check_host() / connect_upstream_tls() sequence
    //    (reverse.rs:599 / :313-332 / :644 respectively) — no forward::UpstreamSpec, no scheme
    //    branch (this fork's connector is always-TLS).

    // 4. Inject: match on `material` (currently only UpstreamAuthMaterial::BearerToken) and build
    //    the header line the same way the existing static_cred injection does
    //    (`format!("{}: {}\r\n", header, format!(credential_format, token))`), using
    //    material.credential_format/header/token — all already resolved by ManagedUpstreamAuth::acquire().

    // 5. Forward + stream response — unchanged mechanics.

    // 6. Audit success: call `audit::log_l7_request` (NOT log_reverse_proxy — Landmine L3, and this
    //    is the ONLY function among the fork's 4 log_* functions that threads ctx.spiffe_context),
    //    with `ctx.spiffe_context: Some(material.spiffe_audit_context())` set on the EventContext,
    //    `auth_mechanism: Some(managed_auth.audit_mechanism())`, `injection_mode:
    //    managed_auth.audit_injection_mode()`, `managed_credential_active: Some(true)`.
}
```

`handle_spiffe_assertion_credential` follows the identical shape, substituting
`spiffe_assertion.cache.get_or_refresh().await` for step 2 (returning a plain `Zeroizing<String>`
access token, injected as `Bearer {token}` into `spiffe_assertion.inject_header`), and its own audit
context (`workload_spiffe_id: spiffe_assertion.cache.workload_spiffe_id.clone()`,
`svid_type: "jwt".to_string()`, `source: "spire-workload-api"`) — build this literal directly rather
than via `UpstreamAuthMaterial::spiffe_audit_context()` (that helper is specific to the
`BearerToken` variant used by `ManagedUpstreamAuth::acquire`; the assertion-cache path has no
`ManagedUpstreamAuth`/`UpstreamAuthMaterial` in its chain at all — it goes straight from
`SpiffeAssertionTokenCache` to an injected header, per credential.rs's design in Plan 113-03).
