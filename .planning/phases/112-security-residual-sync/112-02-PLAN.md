// crates/nono/src/sandbox/mod.rs — NEW public API this commit adds
#[cfg(target_os = "linux")]
pub fn apply_seccomp(
    caps: &CapabilitySet,
    opts: linux::SeccompOpts,
) -> Result<linux::SeccompNetFallback> {
    linux::apply_seccomp(caps, opts)
}

#[cfg(target_os = "linux")]
pub fn apply_seccomp_with_abi(
    caps: &CapabilitySet,
    abi: &DetectedAbi,
    opts: linux::SeccompOpts,
) -> Result<linux::SeccompNetFallback> {
    linux::apply_seccomp_with_abi(caps, abi, opts)
}

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Sandboxed child process -> /proc/<tgid>/task/<tid>/comm | Untrusted child requests a procfs write for GPU device naming; the supervisor must validate the path against the child's own tgid before honoring it |
| Seccomp-notify setup failure -> sandbox posture | A failed openat/network seccomp-notify install or fd handoff must fail the whole sandbox init, not silently degrade to unenforced |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-112-04 | Tampering | `crates/nono/src/sandbox/linux.rs` NVIDIA procfs comm-write path | mitigate | Validate the target `/proc/<tgid>/task/<tid>/comm` path against the sandboxed child's own tgid before the supervisor performs the fd-injected write; reject any tgid mismatch |
| T-112-05 | Elevation of Privilege | seccomp-notify openat/network setup + fd handoff | mitigate | Task 2 makes setup/handoff failures fatal `NonoError` returns instead of a silent warning-and-continue, closing a fail-open gap |
| T-112-06 | Tampering | `Sandbox::apply_external()` semantics | mitigate | Doc-comment correction removes the misleading "installs no rules" framing so callers do not mistake it for a full-sandbox substitute; enforced by Task 2's call-site audit |

Package Legitimacy Gate: N/A — no new `Cargo.toml` dependencies introduced by this absorb.
