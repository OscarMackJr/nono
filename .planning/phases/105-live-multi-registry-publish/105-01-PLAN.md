<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator dispatch <-> irreversible crates.io publish | A crates.io version, once published, can never be replaced or deleted (only yanked, which still burns the number) |
| GitHub Actions secret <-> CI log | CARGO_REGISTRY_TOKEN must never traverse a code path that could echo it into a log |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-105-01-01 | Tampering | An unrelated future tag push accidentally triggering a live crates.io publish | mitigate | publish-crates.yml has no push trigger at all (structural, not conditional) -- grep-verified zero occurrences of `push:` in the file |
| T-105-01-02 | Elevation of scope | A dispatch with an empty/wrong confirm input still executing the publish steps | mitigate | job-level `if: github.event.inputs.confirm == 'PUBLISH LIVE'` gates the entire job before checkout ever runs |
| T-105-01-03 | Information Disclosure | CARGO_REGISTRY_TOKEN appearing in a log line or command echo | mitigate | token threaded exclusively via an env: block consumed by cargo's own `--token`-equivalent env var, never interpolated into a run: string; grep-verified |
| T-105-01-04 | Repudiation | Re-running the workflow against an already-published crate silently double-publishing or hard-failing ungracefully | mitigate | crates-index-poll.ps1 -CheckOnly pre-check skips a crate whose target version is already indexed, matching crates.io's own reject-on-republish semantics -- resumable and safe |

</threat_model>
