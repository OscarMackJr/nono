## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Git tag push -> GitHub Actions job graph | An operator action (Plan 03) that triggers automatic execution of every job in `release.yml` whose `if:` evaluates truthy — jobs not directly re-inspected at push time can silently fail or, worse, silently leak a secret reference into an executing step |
| `publish-crates` job body <-> `CARGO_REGISTRY_TOKEN` secret | A neutralized job must never partially execute a step that references a secret — the neutralization mechanism itself is part of this phase's security surface |
| Locked requirement/roadmap text <-> future planning/execution reads | `REQUIREMENTS.md`/`ROADMAP.md` are treated as authoritative, near-immutable inputs by future `/gsd:plan-phase` runs and by any future maintainer reading this repo's history — stale, disproven gate wording left uncorrected here would misinform a future reader into reintroducing an insecure differentiator |
