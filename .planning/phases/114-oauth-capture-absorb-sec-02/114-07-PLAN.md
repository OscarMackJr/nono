<objective>
Add D-06's cross-path fail-closed guard: a capture-declared route's upstream must be unreachable
via any path except the buffered reverse-proxy handlers (Plans 114-05/114-06). Mirror the existing
SPIFFE guard in `handle_forward_http` exactly (this phase's "one genuinely new guard"), and refine
the CONNECT dispatch's audit `denial_category` so a capture-route CONNECT-bypass is distinguishable
from a plain one — the CONNECT path itself needs NO new deny logic, since `is_route_upstream()`
already blocks CONNECT to every route upstream unconditionally, before any capture-specific
refinement.

Purpose: without this guard, an agent could reach a capture-declared token endpoint via
`http://` forward-proxying or CONNECT and receive the real, unrewritten token — bypassing the
ONLY enforcement point Plans 114-05/114-06 build. This is exactly the WR-13 defect shape
(`112-REVIEW.md`) — one request path of several ignoring a gate the others already have.
Output: `handle_forward_http` denies capture-declared route upstreams; CONNECT's audit trail
distinguishes capture-route denials; both proven by tests.
</objective>

The SPIFFE guard to mirror exactly (`crates/nono-proxy/src/server.rs:1043-1077`, verified live,
full text — `fn handle_forward_http` starts at line 989):
```rust
    // D-03 (113-CONTEXT.md): this forward-HTTP path has no SPIFFE
    // implementation of its own ...
    let host_port = format!("{}:{}", host, port);
    if state.route_store.spiffe_declared_for_upstream(&host_port) {
        warn!(
            "Blocked forward-HTTP request to SPIFFE-declared route upstream {} — this path has \
             no SPIFFE implementation (D-01); use the reverse-proxy path instead",
            host_port
        );
        audit::log_denied(
            Some(&state.audit_log),
            audit::ProxyMode::Reverse,
            &audit::EventContext {
                denial_category: Some(
                    nono::undo::NetworkAuditDenialCategory::SpiffeUnsupportedPath,
                ),
                ..audit::EventContext::default()
            },
            &host,
            port,
            "SPIFFE-declared route upstream: forward-HTTP path has no SPIFFE implementation",
        );
        let response = "HTTP/1.1 403 Forbidden\r\nContent-Length: 0\r\n\r\n";
        stream.write_all(response.as_bytes()).await?;
        return Ok(());
    }
```
The new capture guard is this EXACT shape, placed directly after (or before — order between the
two guards does not matter, both are unconditional early-returns) the SPIFFE block above, with
`spiffe_declared_for_upstream`/`SpiffeUnsupportedPath` substituted for
`capture_declared_for_upstream`/`CaptureUnsupportedPath`. Deliberately **unconditional** — NOT
gated on `state.config.require_auth` — for the same reason the SPIFFE guard isn't: the property
("this route only makes sense through the reverse-proxy path") doesn't depend on whether
session-token auth happens to be enabled for this proxy instance.

The CONNECT dispatch block to refine (`crates/nono-proxy/src/server.rs:1320-1373`, verified live

```rust
                    let denial_category = if is_spiffe_route {
                        nono::undo::NetworkAuditDenialCategory::SpiffeUnsupportedPath

                        nono::undo::NetworkAuditDenialCategory::ConnectBypassesL7
                    };
                    let denial_reason = if is_spiffe_route {
                        "SPIFFE-declared route upstream: CONNECT path has no SPIFFE implementation"

                        "route upstream: CONNECT bypasses L7 filtering"
                    };
                    ...
```
