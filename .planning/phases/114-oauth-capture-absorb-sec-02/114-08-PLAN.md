<objective>
Bring the CLI-facing declarative capture surface online: a new `profile/credential_provider.rs`
module (D-12's named port target) holding the field-path validation logic adapted from upstream,
a `CustomCredentialDef.capture` field wired into `validate_custom_credential()`, and the real
`network_policy.rs` conversion that replaces Plan 114-02's `capture: None` stub with the actual
`RouteConfig.capture` value.

Purpose: let an operator declare `capture = { response_fields = [...] }` on a custom credential in
their profile and have it actually reach the proxy's `RouteConfig` — closing the loop Plan 114-02
opened. D-07's "rebuild the plumbing against the fork's actual per-route shape" applies here: this
fork's `CustomCredentialDef` already IS a per-route credential declaration, so this plan reuses the
wire-format `nono_proxy::config::CaptureConfig` type directly (mirroring how `spiffe`/`aws_auth`
already do) rather than porting upstream's separate `credential_providers`/`credential_routes`
top-level indirection layer, which this fork's model has no structural need for.
Output: `credential_provider.rs`, `CustomCredentialDef.capture`, validated + threaded into the
real `RouteConfig` at launch time.
</objective>

fn validate_custom_credential(name: &str, cred: &CustomCredentialDef) -> Result<()> {
    if cred.aws_auth.is_some() && (cred.credential_key.is_some() || cred.auth.is_some()) { ... }
    if cred.credential_key.is_some() && cred.auth.is_some() { ... }
    if cred.spiffe.is_some()
        && (cred.credential_key.is_some() || cred.auth.is_some() || cred.aws_auth.is_some())
    { ... }
    // At least one of credential_key, auth, aws_auth, or spiffe must be set.
    if cred.credential_key.is_none()
        && cred.auth.is_none()
        && cred.aws_auth.is_none()
        && cred.spiffe.is_none()
    {
        return Err(NonoError::ProfileParse(format!(
            "custom credential '{}' must have either 'credential_key', 'auth', 'aws_auth', or \
             'spiffe' set", name

is a deliberate design decision (capture is response-direction, the other four are

extend the "at least one of" check: add `&& cred.capture.is_none()` to its condition, and add
`'capture'` to its error message's field list, since a route with ONLY `capture` set (no other
auth mechanism — the primary use case, a bare token-endpoint route) must be valid.

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Profile file (untrusted-shaped, operator-authored) -> CustomCredentialDef -> RouteConfig | Profile-declared capture config must be validated before it reaches the proxy — a malformed path or an over-large cap value must be rejected at load time, not discovered at request time |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-114-10 | Denial of Service | `max_response_bytes` profile field | mitigate | `validate_capture_config` rejects values above `CAPTURE_MAX_RESPONSE_BYTES_CEILING` at profile-load time, before any request is ever served |
| T-114-11 | Input Validation | `response_fields`/`request_nonce_fields` dot-paths | mitigate | Empty/malformed paths (leading/trailing/double dots) rejected at load time — ported from upstream's proven field-path validation shape (D-12) |
