<objective>
Add the capture-specific audit vocabulary this phase's enforcement point and guard will emit
into: a pure-data `CaptureAuditContext` struct and a `CaptureUnsupportedPath` denial-category
variant in the core `nono` crate, plus the `nono-proxy` audit plumbing to carry and emit them.
This is Wave 1 foundation work — Plans 114-05/114-06 (the buffer-and-rewrite helper) and
114-07 (the D-06 cross-path guard) both consume these types and must not need a second edit to
this enum, mirroring how Phase 113 (`113-01-PLAN.md`) added `SpiffeUnsupportedPath` ahead of need.

Purpose: give the enforcement point and the fail-closed guard a way to record what happened
(which route, which fields were rewritten, which denial fired) without ever recording a real
OAuth token — satisfying D-08's "must never contain a raw token" constraint and D-09's "SC3 is
LIVE, ADR-86 boundary must hold" constraint structurally, not by convention.
Output: `CaptureAuditContext`, `NetworkAuditDenialCategory::CaptureUnsupportedPath`,
`EventContext.capture_context`, `NetworkAuditEvent.capture_context`, wired into all 4 existing
`push_event` call sites in `audit.rs`.
</objective>
