`Assert-TrustedSignature -Path <string> -Mode Strict|Informational` — the sole public entry point.
- `-Path` is `[Parameter(Mandatory)][string]`, validated via `Test-Path -LiteralPath` (never `-Path`,
  to avoid wildcard-expansion path-injection per CLAUDE.md path-handling guidance).
- `-Mode` is `[Parameter(Mandatory)][ValidateSet('Strict','Informational')][string]` — no default
  value, so a call site that omits `-Mode` throws (fail-closed), never silently picks a mode.
- Returns a `[pscustomobject]` with at least `Path`, `GasStatus`, `SignToolExitCode`, `Passed`
  (`$true`/`$false` in Strict mode, `$null` in Informational mode).
- Internal supporting functions (not required to be exported, but must exist and be independently
  testable): `Find-Signtool`, `Invoke-SignToolVerify`, `Get-FlagClassification`,
  `Get-ChainClassification`, `Get-CertificateRevocationUrls`, `Write-ChainDiagnostic`,
  `Invoke-VerifyWithTransientRetry`.
- No top-level executable statements in the file. No `$env:GITHUB_*` / `$env:CI` reads anywhere —
  Phase 103 reuses this helper outside CI.
</interfaces>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI runner (windows-latest) file system → `Assert-TrustedSignature -Path` | Path is repo-controlled build output today, but the function is a reusable library boundary consumed by 3+ call sites (Plan 02) and Phase 103 |
| Signer certificate chain → CRL/OCSP network endpoints | `Get-ChainClassification`'s `X509Chain.Build()` reaches out to revocation endpoints — untrusted network responses cross here |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-101-01 | Tampering | `Assert-TrustedSignature` Strict branch | mitigate | D-01 AND-gate (GAS + signtool both must pass) plus the byte-for-byte-preserved `Status -ne 'Valid'` condition; acceptance criteria grep for this exact condition and confirm it gates a `throw` |
| T-101-02 | Tampering | `Get-ChainClassification` / `Invoke-VerifyWithTransientRetry` | mitigate | Never sets `X509RevocationMode.NoCheck`; retry only re-attempts the whole verify and always returns the LAST result — an exhausted transient never becomes `Passed = $true` |
| T-101-03 | Tampering | `Assert-TrustedSignature -Path` parameter | mitigate | `Test-Path -LiteralPath` (never `-Path`) before any signtool/GAS call — avoids wildcard-expansion path-injection per CLAUDE.md |
| T-101-04 | Information Disclosure | `Write-ChainDiagnostic` | accept | Subject/Issuer/Thumbprint strings originate from the Trusted Signing service's own issued certs (not attacker-controlled input in this CI-signing context); dumped only on the failure path, into CI logs already covered by the repo's existing log-visibility posture |
