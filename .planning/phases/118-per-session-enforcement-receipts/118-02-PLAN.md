<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Sink directory ACL | The receipt sink directory sits in a filesystem location both the supervisor and the confined child (same user) can reach by path — the ACL/label is the ONLY thing preventing the child from reading or tampering with it. |
| `HKLM\SOFTWARE\Policies\nono` | Machine-wide, admin-writable only in a well-run fleet — a confined process at Low-IL/AppContainer cannot write HKLM, so this is a legitimate fail-closed control point, not a bypassable one. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-118-05 | Elevation of Privilege / Information Disclosure | Receipt sink directory (used by Plan 118-05/06) | mitigate | `deny_sid_on_path` (this plan) + `try_set_mandatory_label` (existing) together — D-08's both-not-either rule. Neither alone covers every arm (restricted-token reads bypass DACL-only restriction checks; AppContainer/Medium-IL children are missed by the mandatory label alone). |
| T-118-06 | Tampering | `require_receipts` malformed registry value | mitigate | Abort (not degrade) on present-but-unreadable/malformed, per D-04's explicit choice of the egress lifecycle — a fleet admin who configured this knob must never have it silently no-op. |
| T-118-07 | Denial of Service (self-inflicted) | `require_receipts=true` on a host where the sink cannot be created/ACL'd | accept (documented) | This is the intended fail-closed behavior per D-04 — an admin who requires receipts fleet-wide accepts that a host unable to satisfy the guarantee refuses launches. Plan 118-07/118-08 wire the actual abort; this plan only defines the policy read. |
</threat_model>
