<objective>
Give `nono.exe` a real, complete 13-row census (RCPT-01's "every confined session emits a receipt
naming which layers were confirmed active" requirement), built as a pure pass alongside — never
inside — the existing decision function, per Research Finding 1 and Pitfall 4. Pair it with the
behavioral half of D-14's content-free proof (the sentinel round-trip) and the census-completeness
drift guard, since a producer without its own completeness/leak guard is exactly the anti-pattern
critical constraint 4 forbids.

Purpose: this is the primary data source for the CLI's own receipts (wired in Plan 118-07) and the
pattern every downstream binary-specific plan (daemon 118-04, broker 118-06) follows.
Output: `census_from_entries` + `build_enforcement_receipt` in `attestation.rs`; `LayerId` consumed
from core in `layer_registry.rs`; sentinel round-trip test; extended census-completeness meta-test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `classify_row` probes → census rows | The census must reflect FRESH probes, not cached/stale decision-function state — a stale-value bug here would make the receipt lie about what was actually checked. |
| `AttestationInput.expected_session_sid` → `EnforcementReceipt` | The one caller-supplied string that flows this deep into the pipeline; the sentinel test exists specifically because this is the highest-risk leak point structurally available today. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-118-08 | Repudiation | `census_from_entries` silently reusing `decide_from_entries`'s discarded verdicts instead of fresh `classify_row` calls | mitigate | Test 3 in Task 1 asserts census rows match independently-computed `classify_row` results, not cached decision-loop state (D-01, Finding 1's core lesson: predicate width, not just placement). |
| T-118-09 | Information Disclosure | `expected_session_sid` (a Windows SID string, not itself a path, but the nearest available "caller-supplied string" injection point) leaking into the serialized receipt | mitigate | Sentinel round-trip (Task 2) with a documented negative-control perturbation proving the test can fail — D-05/D-14. |
| T-118-10 | Tampering | A future refactor of `decide_from_entries` accidentally sharing mutable state with `census_from_entries` | accept (documented) | Both functions call the same pure, side-effect-free `classify_row` — Task 1's design explicitly keeps them as two independent loops over the same read-only input rather than factoring a shared mutable accumulator, per Pitfall 4's guidance. |
</threat_model>
