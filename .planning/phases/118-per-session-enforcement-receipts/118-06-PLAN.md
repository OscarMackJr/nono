<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `nono-cli` (producer) → `nono-shell-broker` (consumer), across a process spawn | The broker trusts the env-var wire contract completely — a version-skewed pair (old broker, new nono-cli or vice versa) must fail toward under-claiming, never over-claiming. |
| Broker's own receipt sink write ↔ `receipt_sink.rs`'s independent write | Two independent writers to the same directory, correlated only by session id and directory location convention — no shared code, no shared lock (D-15). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-118-18 | Repudiation | Version-skewed nono-cli/nono-shell-broker pair (old broker reading a new wire-contract shape, or vice versa) | mitigate | An unrecognized/absent row fails toward `Unconfirmed`, never silently dropped from the census or promoted to `NotApplicable`/`Confirmed` (D-27) — a mismatched pair produces a visibly degraded receipt, not a falsely-clean one. This is a RUNTIME guard, distinct from Task 3's BUILD-TIME name-match guard — the two are complementary, covering different failure windows (a bad release vs. a live version-skewed fleet). |
| T-118-19 | Tampering | Broker's hand-rolled sink writer diverging from `receipt_sink.rs`'s JSONL shape over time (two independently maintained implementations) | accept (documented) | Acceptable per D-15's architecture; mitigated by the acceptance criterion requiring identical field names, and by Plan 118-09's command family being the actual cross-check (if the shapes diverge, `nono receipt list/verify` breaks visibly on broker-written records — a loud failure, not silent). |
| T-118-20 | Elevation of Privilege | Broker's own confined grandchild reading its own not-yet-written receipt during the CREATE_SUSPENDED window | mitigate | The child is suspended (never executes an instruction) until AFTER `ResumeThread`, which happens AFTER the receipt write completes — same D-03 ordering guarantee as the other two binaries. |
| T-118-21 | Repudiation | A per-LayerId wire-reachability regression that Task 3's name-match test cannot see (e.g. a row's classification silently flipping without the env-var NAMES changing) | accept (documented) | Task 1's partition test already covers this class on the nono-cli side (any row losing coverage breaks the union==ALL invariant); no equivalent static check is possible on the broker side by design (D-27 rejected a static per-LayerId table there) — the residual risk is covered at runtime by the fail-safe (T-118-18) and, for the actual end-to-end wire, by Plan 118-10's manual confined-child checkpoint. |
</threat_model>
