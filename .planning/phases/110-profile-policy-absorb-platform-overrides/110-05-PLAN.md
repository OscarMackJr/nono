<objective>
Wire the CapabilitySet mechanism (plan 110-03) to its two independent profile-facing consumer
pipelines: the profile pathway (`capability_ext.rs::CapabilitySet::from_profile`, consuming plan
110-04's `NetworkConfig.open_port_range`) and the manifest pathway
(`manifest_convert.rs::TryFrom<&CapabilityManifest> for CapabilitySet`, consuming a NEW
`PortConfig.localhost_range` schema field). These are two SEPARATE, non-overlapping code paths in this
codebase — a profile-driven `nono run --profile` invocation never touches `manifest_convert.rs`, and a
manifest-driven `--config` invocation never touches `capability_ext.rs`'s profile logic — so both need
their own wiring and their own validation, ported independently from upstream `d5803b99`. Also
threads display-only support through `profile_cmd.rs`/`output.rs` so an operator can actually SEE the
new fields. Completes the remaining CLI-side half of PROF-03 alongside plans 110-04 and 110-06.

Purpose: without this plan, plan 110-04's `open_port_range` field is schema-valid and parses, but has
zero enforcement effect — the exact "schema key that deserializes but reaches no enforcement path"
failure mode CONTEXT.md's `<specifics>` names as this milestone's most-caught defect class.

Output: `capability_ext.rs` gains a 3-line sibling loop next to the existing `open_port` handling.
`manifest_convert.rs` gains its own independent conversion loop with its own start<=end and
macOS-cumulative-cap checks (this is intentional upstream-authored duplication across the two
pathways, not dead code — the manifest pathway has no `profile_runtime.rs` equivalent to validate
ahead of time). `capability-manifest.schema.json` gains `PortConfig.localhost_range`, which is
typify-generated at build time into `crates/nono/src/manifest.rs` — this plan edits ONLY the JSON
schema, never a hand-written Rust struct for the manifest type.
</objective>

manifest_convert.rs — inside `impl TryFrom<&CapabilityManifest> for CapabilitySet`'s existing
`if let Some(ref ports) = net.ports { ... }` block (verified today, the `for port in &ports.localhost {
... caps = caps.allow_localhost_port(p); }` loop is the last statement in that block), add
IMMEDIATELY AFTER it:
```
let mut raw_ranges: Vec<(u16, u16)> = Vec::new();
for &[start, end] in &ports.localhost_range {
    let start_u = start.get();
    let end_u = end.get();
    let (start, end) = match (u16::try_from(start_u), u16::try_from(end_u)) {
        (Ok(s), Ok(e)) => (s, e),
        _ => return Err(NonoError::ConfigParse(format!(
            "localhost_range entry [{start_u}, {end_u}] is invalid: ports must be in 1-65535"))),
    };
    if start > end {
        return Err(NonoError::ConfigParse(format!(
            "localhost_range entry [{start}, {end}] is invalid: start must be <= end")));
    }
    raw_ranges.push((start, end));
}
#[cfg(target_os = "macos")]
{
    let merged = merge_port_ranges(&raw_ranges);
    let total: u32 = merged.iter()
        .map(|&(s, e)| (e as u32).saturating_sub(s as u32).saturating_add(1))
        .fold(0u32, |acc, n| acc.saturating_add(n));
    if total > crate::capability::MACOS_PORT_RANGE_LIMIT {
        return Err(NonoError::ConfigParse(format!(
            "localhost_range entries expand to {} unique ports, which exceeds the macOS limit of {} \
             (sandbox_init crashes above ~17,770 rules); use smaller or fewer ranges",
            total, crate::capability::MACOS_PORT_RANGE_LIMIT)));
    }
}
for (start, end) in raw_ranges {
    caps = caps.allow_localhost_port_range(start, end)?;
}
```
Add `#[cfg(target_os = "macos")] use crate::capability::merge_port_ranges;` to this file's imports
