Absorb upstream `b620ed8e` (#1305, `bun` runtime preset) and `f016b2d5` (#1387, `mise` runtime
preset). Implements PROF-04, the last of this phase's requirements. Deliberately kept in its own

discretion constraint).

Purpose: add two more built-in runtime-development profiles matching the fork's existing
`go-dev`/`python-dev`/`node-dev`-style pattern, and PROVE they resolve by name — per D-11, "a schema
key that deserializes but reaches no enforcement path is this milestone's most-caught defect class",
the existing `test_schema_validates_builtin_profiles_in_policy_json` test only proves schema
conformance, not that `bun-dev`/`mise-dev` actually load and carry their group.

**Schema-shape correction (found during grounding, not in RESEARCH.md/PATTERNS.md):** upstream's own
JSON diff for both commits uses a `"groups": {"include": [...]}"` shape at the profile level. This
does NOT match the fork's `Profile`/`SecurityConfig` struct shape, which has no top-level `groups`
key — the fork expresses group membership as `"security": {"groups": [...]}"` (a flat array), exactly
as the existing `go-dev` profile does. This plan does NOT copy upstream's JSON verbatim; it adapts the
group-membership shape to the fork's own established `security.groups` array pattern while keeping
everything else (descriptions, paths, meta block shape) faithful to upstream's content.
</objective>
