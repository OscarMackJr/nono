<objective>
Absorb upstream `ae1c513e` (#1371, `platform_overrides` field) and `719975cf` (#1380, extends-
preservation + post-merge re-validation fix) verbatim. Implements PROF-01.

Purpose: give the fork a per-OS profile-patch vehicle so Windows-specific settings (today scattered
as top-level `windows_*` flags) have a structural home, without breaking any profile that still uses
the old flags and without letting an override silently vanish when the profile that declares it is
itself a base for `extends`.

Output: `Profile` gains an `Option<PlatformOverrides>` field, applied once per `finalize_profile` call
(after `extends` resolution, before group-merge), using the SAME `merge_profiles` machinery every
other inheritance step in this file already uses — an override can only add/tighten via the existing
child-wins/dedup-append/deny-union rules, never silently replace. Because `PlatformOverride` wraps a
full `Profile`, the existing `windows_low_il_broker`/`windows_interpreters` fields are automatically
reachable inside `platform_overrides.windows` with NO new precedence code required — `merge_profiles`'s
existing OR/dedup-append semantics for those two fields (already present, Phase 51/71 D-02) apply
unchanged when the override is merged in as a "child". This plan proves that composition with explicit
tests rather than leaving it an unverified side effect.

**D-08a (amended 2026-07-30, operator decision — narrows D-08; checker-verified 2026-07-30):**
"`platform_overrides.windows` WINS" applies to ORDINARY settings only. `windows_low_il_broker` and
`windows_interpreters` are the two security-opt-in flags this plan does NOT give new-form precedence
to — they keep their existing fail-secure OR/union semantics (`base.windows_low_il_broker ||
child.windows_low_il_broker` at `profile/mod.rs:3494`, added deliberately in Phase 51/T-51A-02 so a
child profile cannot silently disable a security opt-in its base enabled; `windows_interpreters` is
the analogous `dedup_append` union at `profile/mod.rs:3499`). Reusing `merge_profiles` unmodified for
these two fields is therefore the CORRECT mechanism — an override may only ADD/tighten, never
silently disable/remove, matching CLAUDE.md's "Fail Secure... never silently degrade to a less secure
state" / "when in doubt, choose the more restrictive option." Phase 51's existing regression test,
`merge_profiles_or_semantics_base_true_child_false` (`profile/mod.rs:8142`), MUST stay green and MUST
NOT be edited by this plan. Task 3 below adds the one new test that actually distinguishes this
fail-secure OR behavior from new-form-wins behavior — the two originally-planned D-08 back-compat
tests (`false+true->true`, `absent+true->true`) cannot tell the two semantics apart, since both
produce the same result for those inputs.

`apply_platform_overrides` (ported verbatim):
```
fn apply_platform_overrides(mut profile: Profile) -> Result<Profile> {
    let Some(mut override_profile) = profile
        .platform_overrides
        .take()
        .and_then(|po| po.for_current_platform())
        .map(|o| o.0)
    else {
        return Ok(profile);
    };
    override_profile.meta = profile.meta.clone();
    Ok(merge_profiles(profile, override_profile))
}
```

`merge_platform_overrides`/`merge_platform_override_slot` (ported verbatim from `719975cf`):
```
fn merge_platform_overrides(
    base: Option<PlatformOverrides>,
    child: Option<PlatformOverrides>,
) -> Option<PlatformOverrides> {
    match (base, child) {
        (None, None) => None,
        (Some(b), None) => Some(b),
        (None, Some(c)) => Some(c),
        (Some(b), Some(c)) => Some(PlatformOverrides {
            macos: merge_platform_override_slot(b.macos, c.macos),
            linux: merge_platform_override_slot(b.linux, c.linux),
            windows: merge_platform_override_slot(b.windows, c.windows),
        }),
    }
}

fn merge_platform_override_slot(
    base: Option<Box<PlatformOverride>>,
    child: Option<Box<PlatformOverride>>,
) -> Option<Box<PlatformOverride>> {
    match (base, child) {
        (None, None) => None,
        (Some(b), None) => Some(b),
        (None, Some(c)) => Some(c),
        (Some(b), Some(c)) => Some(Box::new(PlatformOverride(merge_profiles(b.0, c.0)))),
    }
}
```
