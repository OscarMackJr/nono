<objective>
Absorb the library/proxy-crate half of upstream `1619275c` (#1415, profile-declared `no_proxy`
bypass) into `nono-proxy` — the mechanism and its non-negotiable validators (CONTEXT.md D-06), and
the D-07-mandated proof that the fork's existing `localhost`/`127.0.0.1` NO_PROXY behavior survives
the replacement of the static `no_proxy_parts` vec with the upstream `push_no_proxy_entry`
pipeline. Implements NET-03 (proxy-crate half; CLI-side wiring is Plan 109-03).

Purpose: `no_proxy` is a bypass surface in a default-deny tool — an entry overlapping
`allow_domain` would silently defeat filtering. The validators are not optional trim material
(D-06); this plan makes their absence a detectable failure, not a documentation gap.

Output: `nono-proxy` gains a validated `no_proxy` config surface and a rewritten NO_PROXY-building
pipeline, proven non-regressing on the fork's pre-existing loopback-bypass behavior.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| profile no_proxy -> proxy filtering | An operator-authored profile `no_proxy` list is a declared bypass surface in an otherwise default-deny proxy |
| parent shell env -> child NO_PROXY | The parent process's own `NO_PROXY`/`no_proxy` env vars must not silently widen the child's bypass list (D-07) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-109-05 | Elevation of Privilege | `no_proxy` vs `allow_domain`/route-upstream overlap | mitigate | `validate_no_proxy_allowed_host_conflicts`/`validate_no_proxy_route_conflicts` reject any overlapping entry before `ProxyHandle` construction (Task 1+2) |
| T-109-06 | Tampering | Parent-shell `NO_PROXY`/`no_proxy` inheritance | mitigate | start-up filtering of the parent's own NO_PROXY value per D-07, so an inherited operator/CI env var cannot silently widen the child's bypass list |
| T-109-07 | Elevation of Privilege | `bare_single_label_suffix_overlaps_host` omission | mitigate | explicit test coverage per the `<behavior>` block; a bare single-label suffix (e.g. `com`) must be flagged as overlapping, not accepted as a narrow exact-host bypass |
| T-109-SC | Tampering | npm/pip/cargo installs | mitigate | no new external dependencies introduced by this plan |
</threat_model>
