<objective>
Absorb upstream `3b207eeb` (#1374, `deny_domain`) per **ADR-108's ADAPT decision** (deny layer
only, never an allowlist substitute) and **CONTEXT.md D-04/D-05** (the mechanism, not the
already-settled posture). Implements NET-01.

Purpose: give operators an "allow everything except these domains" deny mechanism without ever
letting a deny-only profile silently degrade to default-allow — the exact gap ADR-108 found in
upstream's verbatim design.

Output: `HostFilter`/`ProxyFilter` gain a caller-supplied deny-suffix mechanism (library, policy-
free); `network_policy.rs` gains a CLI-side resolver extension that both plumbs `deny_domain` end-
to-end and selects a fail-closed filter construction; a new CLI-side validator hard-errors a
deny-only profile at BOTH `nono run` and `nono wrap` entry points, per D-04's "a guard on only one
entry point is a bypass" rule.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| profile/CLI -> proxy filter | Untrusted operator-authored profile JSON / CLI args define deny/allow host lists consumed by `HostFilter`/`ProxyFilter` |
| CLI entry points -> proxy activation | `nono run` (command_runtime.rs) and `nono wrap` (launch_runtime.rs) are two independent code paths that must both enforce the same fail-closed posture |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-109-01 | Elevation of Privilege | `network_policy.rs::build_proxy_config` | mitigate | deny-only profiles set `strict_filter: true` (defense-in-depth, Task 2) in addition to being hard-rejected at parse time (Task 3) — two independent layers so neither alone is a single point of failure |
| T-109-02 | Elevation of Privilege | `sandbox_prepare.rs::validate_deny_domain_requires_allow_domain` | mitigate | validator wired into BOTH `command_runtime.rs:149` and `launch_runtime.rs:361` (D-04) — a guard on only one entry point is a bypass; both are explicit acceptance criteria |
| T-109-03 | Tampering | `HostFilter::with_denied_hosts` wildcard matching | mitigate | suffix match requires `lower_host.len() > suffix.len()`, preventing the bare apex domain from matching its own wildcard deny entry (ported upstream test asserts this) |
| T-109-04 | Information Disclosure | `--deny-domain` env var `NONO_DENY_DOMAIN` | accept | mirrors the existing `NONO_ALLOW_DOMAIN` env-var exposure model; domain names are not secrets |
| T-109-SC | Tampering | npm/pip/cargo installs | mitigate | no new external dependencies introduced by this plan; library-only additive Rust code |
