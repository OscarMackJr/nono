<objective>
Absorb the CLI-crate half of upstream `1619275c` (#1415) — profile-declared `no_proxy` parsing,
schema, and the two remaining D-06 validators that operate above the `nono-proxy` crate boundary
(`validate_profile_no_proxy`, `validate_proxy_launch_no_proxy_conflicts`,
`validate_expanded_proxy_no_proxy_conflicts`). Depends on Plan 109-02's `nono-proxy` crate
validators (`validate_no_proxy_entry`, `no_proxy_entry_overlaps_host_pattern`). Implements NET-03.

Purpose: closes the D-06 overlap-detection loop at every layer a `no_proxy` entry can be declared —
directly on a profile, inherited through `extends`, or reached via `allow_domain` group-name
expansion — so none of the three named upstream regression tests
(`rejects_allow_domain_overlap`, `rejects_inherited_no_proxy_allow_domain_overlap`,
`rejects_group_expanded_no_proxy_overlap`) can be silently trimmed.

Output: `nono run`/`nono wrap` reject a conflicting `no_proxy` profile at load time, before any
proxy activation.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| profile file -> parsed Profile struct | Untrusted profile JSON parsed and merged (extends inheritance) before any proxy activation |
| CLI flags + resolved profile -> ProxyLaunchOptions | Two independent input surfaces (profile no_proxy, `--allow-domain` CLI overrides) must be checked together, post-merge, post-group-expansion |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-109-08 | Elevation of Privilege | `merge_profiles`/`finalize_profile` extends resolution | mitigate | `validate_profile_no_proxy` runs on the fully-merged profile so a base-profile `allow_domain` inherited through `extends` still catches an overlapping child `no_proxy` entry |
| T-109-09 | Elevation of Privilege | network-policy group-name expansion | mitigate | `validate_expanded_proxy_no_proxy_conflicts` runs AFTER `expand_proxy_allow`/`partition_allow_domain`, so a `no_proxy` entry cannot bypass filtering by targeting a host reachable only via an expanded group name |
| T-109-SC | Tampering | npm/pip/cargo installs | mitigate | no new external dependencies introduced by this plan |
</threat_model>
