<objective>
Close WR-21: two residuals from Plan 117-25's otherwise-correct WR-09 fix (which made
`SecurityEventLayerInner`'s fields private again and routed cross-module chain access through one
accessor).

1. **Lock-scope divergence.** `emit_attestation_event` (via `advance_and_snapshot`) releases the
   chain mutex on return, THEN builds and emits its `SecurityEvent` outside the lock — chain
   advancement and record emission are no longer atomic for this event type. `emit_override_event`
   (the sibling emitter, unchanged) still holds the lock across its own emit. Two concurrent
   emitters can now advance the chain in order A,B and write Event Log records in order B,A. Each
   record still carries its own correct `chain_head`, so this is an ordering/consistency erosion,
   not a forgery risk — but it is an undocumented divergence in a tamper-evidence mechanism between
   two emitters that should behave identically.
2. **A stale justification for `pub(crate)`.** `SecurityEventLayer::inner`'s field-level comment
   ("see the NR3-05 follow-up comment on `SecurityEventLayerInner`") points at a comment Plan 117-25
   rewrote to explain why `SecurityEventLayerInner`'s OWN fields are private — it says nothing about
   why `inner` itself stays `pub(crate)`. The only remaining cross-module use of `inner` directly is
   a `#[cfg(test)]` mutex-poisoning helper in `attestation_downgrade_event.rs`, giving production
   code crate-wide `.lock()` access to the audit-chain mutex for a test-only reason.

Purpose: restore lock-scope parity between the two sibling emitters, and narrow `inner`'s visibility
to match what production code actually needs — removing the `#[allow(dead_code)]`-adjacent stale
justification per this round's stated preference to remove the need for such allowances where
possible.
Output: `advance_and_emit` (replacing `advance_and_snapshot`) holding the lock across the full
build-advance-emit sequence; a `poison_for_test` method with its own explicit
`clippy::unwrap_used` justification; `inner` narrowed to private.
</objective>
