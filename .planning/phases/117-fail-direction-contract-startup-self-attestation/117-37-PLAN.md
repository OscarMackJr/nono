<objective>
Close CR-05 — a FOURTH D-28 layer-name leak site that round 3's CR-03 enumeration missed because
it stopped at the boundary of `apply_startup_attestation_gate` (the function it was fixing) and
never followed `emit_attestation_event`'s own call chain downstream. The chain: `apply_startup_
attestation_gate` -> `emit_attestation_event` -> `emit_security_event(&security_event)` ->
`write_security_event_log(Warning, 10011, &payload)`, where `payload` is the full serialized
`SecurityEvent` JSON INCLUDING `downgraded_layers` (the comma-joined `LayerId` `Debug` names D-28
exists to withhold from the confined process). `write_security_event_log`'s documented D-03
fallback — reached whenever the `nono` Application-log source is not registered, i.e. any dev host
or any install where `nono setup` has not run — is a raw `eprintln!` of that full payload to the
supervisor's stderr, the exact shared channel the confined child reads on the non-detached-stdio
path. This is not a `tracing` call, so `log_target_is_private()` structurally cannot gate it — it
was invisible to CR-02/CR-03's entire predicate-based approach by construction.

Per this round's governing instruction to enumerate OUTWARD across module boundaries rather than
naming a file set up front: this plan's Task 1 requires the executor to independently re-derive
the full `downgraded_layers` read/render call graph (not merely trust this objective's account of
it) before writing the fix, and to state the enumeration boundary used and why it is complete.

Purpose: close the D-28 leak at its true site rather than only inside the function CR-03 patched,
and prove the rendered fallback TEXT — not just the in-process event struct — never carries a
layer name.
Output: `write_security_event_log`'s NULL-handle fallback renders a redacted copy of the event;
an extended withholding test asserting on the rendered fallback string itself.
</objective>
