<objective>
Add a policy-free, platform-neutral attestation primitive to `crates/nono`: a shared 4-state status
type (D-18) plus the raw OS probe functions (D-17) that query a suspended child process's actual
token/job state from outside it. This is the library-side half of CINT-02 — mechanical
observation, no policy about which layers are required or what a missing layer should do (that
stays CLI-side per D-02, built in Plan 08).

Purpose: three independent spawn sites (`exec_strategy_windows/launch.rs`,
`nono-shell-broker/src/main.rs`, `agent_daemon/launch.rs`) all need to observe a suspended child's
real OS state before `ResumeThread`. Only two of those three are in the `nono-cli` crate; the
broker is a separate binary that already links `nono` directly. Putting the mechanical probes here
gives all three call sites one shared, tested primitive instead of three independent
re-implementations of `GetTokenInformation`/`IsProcessInJob` calls (RESEARCH finding 1).
Output: `crates/nono/src/attestation.rs` (new), wired into `crates/nono/src/lib.rs`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| supervisor process → suspended child process (kernel object query) | The probe functions read the child's OS-level state from outside; the child never asserts anything about itself into this module |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-117-02 | Spoofing | attestation trusting a self-report | mitigate | D-19 invariant enforced structurally: every function in this module takes a `HANDLE` and performs an OS query against it — there is no function signature anywhere in this module that accepts a claim string/struct FROM the target process. A future reviewer can verify this by grepping the module for any parameter shaped like "child-supplied data" |
| T-117-12 | Denial of Service | probe failure on a malformed/closed handle | mitigate | Every probe returns `Err` on OS-call failure rather than panicking (Task 2 behavior tests), so a hostile or already-terminated child cannot crash the supervisor via this path |
| T-117-SC | Tampering | supply chain | accept | No new crate dependencies; `TokenAppContainerSid`/`TokenRestrictedSids` are already covered by `crates/nono/Cargo.toml`'s existing `Win32_Security` windows-sys feature |
