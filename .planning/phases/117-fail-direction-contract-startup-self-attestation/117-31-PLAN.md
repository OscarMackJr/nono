<objective>
Close WR-13: Plan 117-24 wrote two source-scanning symbol matchers in one pass.
`contains_fn_exact` (`layer_registry_meta_test.rs`) got both the identifier-prefix rule AND a
trailing-boundary rule (WR-10's fix). `content_defines_symbol` (`layer_registry_selfcheck.rs`) got
only the prefix rule — nothing inspects the character immediately after the matched needle. Two
live consequences: (1) a prefix-preserving rename
(`create_restricted_token_with_sid` -> `create_restricted_token_with_sid_v2`) still satisfies
`content_defines_symbol`, falsifying the SPEC's own claim that "a renamed or removed enforcing
function fails the build" for the rename half — confirmed empirically against
`nono-shell-broker/src/main.rs`, where the cited symbol `::run` is satisfied by `fn
run_fails_when_app_container_forced_unavailable` just as well as by the real `pub fn run`; (2) the
function throws away the `Type::` qualifier entirely, so `Type::method` citations verify only the
bare method name — `WfpNetworkBackend::install` and `FirewallRulesNetworkBackend::install` both
reduce to the needle `fn install` in the same file and become indistinguishable, as do two of three
guards in `dacl_guard.rs` sharing the method name `snapshot_and_apply`.

Purpose: one shared boundary rule for both matchers (so the next round cannot fix one and forget the
other again), plus qualifier-aware resolution so a `Type::method` citation actually verifies the
right method.
Output: `is_ident_boundary` in `tests/common/mod.rs`; `content_defines_symbol` gains the boundary
check and `impl Type` resolution.
</objective>
