**Item-1 fix (checker pass 3, 2026-08-09) — broker-abort-only structural constraint.** Plan 01's
registry mechanically enforces (via a discovery-based unit test, `broker_expected_rows_are_abort_only`)
that every row expected at `EntryPath::Broker` has `outcome: ContractOutcome::Abort` — because a
non-`Abort` broker-expected row would be silently excluded from both `attest_and_decide` (Blocker-1)
and `required_layers_for_broker` (Plan 08), going completely unattested on the broker arm. The SPEC
must name this constraint explicitly, not just let it live as an enforced-but-unexplained test.

**Item-2 fix (checker pass 3, 2026-08-09) — downgrade-banner per-session dedup.** `claude_code_hook.rs`
re-enters the direct spawn path on every tool call; on a host where a row (WFP being the named
candidate under D-18's own accepted tension) persistently sits non-`Confirmed`, an un-deduplicated
banner would fire on every single tool invocation. **Decision:** the banner dedupes per session, not
per spawn — the first occurrence of a given downgraded-layer-set always prints (the D-27/Warning-8
no-silent-downgrade property is preserved: only an *identical repeat* within the same session is
suppressed, `--silent` never suppresses the first occurrence, and no new global silence switch is
introduced). This is a contract-visible behavior (an operator on an affected host will observe one
banner per session, not one per tool call) and must be recorded in the SPEC, not left implicit in
code comments alone.
