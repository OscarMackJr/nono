<objective>
Close CR-02 (BLOCKER-adjacent, D-28 violation): Plan 117-16's unconditional
`tracing::warn!(downgraded_layers = %dedup_key, ...)` in `apply_startup_attestation_gate`'s
`ProceedDowngraded` arm carries specific downgraded `LayerId` names, justified by a comment claiming
tracing never reaches the confined child's stderr. That premise is false — `init_tracing_with_security`'s
default arm (no `--log-file`, the overwhelmingly common `nono run` / per-tool-call hook path) and its
file-open-failure fallback arm both route to `std::io::stderr`, which the confined child shares on the
non-detached-stdio path. This is the exact reconnaissance D-28 exists to prevent.

Also close WR-04: `NonoError::remediation()`'s `ClearStaleLayerResidue` arm (added by Plan 117-13 for
NR3-01) is never called anywhere on the primary CLI error-printing path in `main.rs`, so the
remediation guidance is invisible to an operator who hits a genuine `LayerAttestationFailed`.

Purpose: the downgrade-detail channel must respect the D-28 boundary the code already draws elsewhere
(the coarse, count-only banner in `output.rs`), and a structured remediation the library already
computes must actually reach the operator.
Output: a private-channel query in `cli_bootstrap.rs`, a gated warn in `launch.rs`, a corrected banner
text in `output.rs`, and a remediation-rendering hookup in `main.rs`.
</objective>
