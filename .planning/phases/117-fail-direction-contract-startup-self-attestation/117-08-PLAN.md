<objective>
Build the CLI-side attestation decision module: the function every gate-insertion site (Plans 10,
11) calls with a suspended child's process handle and gets back a single `AttestationDecision`
(proceed / proceed-downgraded / abort). This module owns the POLICY half of CINT-02 (which layers
are required on which arm, what a missing one means) per D-02, consuming the mechanical probes
Plan 05 built and the registry Plan 01 built. It also defines the wire contract nono-cli uses to
tell the broker (a separate binary that cannot import this module) which layers it must itself
enforce.

Purpose: give Plans 09/10/11 one call, one return type, and a settled architecture decision for the
"one shared gate helper vs. three re-implementations" question RESEARCH raised — resolved here as:
mechanical probes are shared (`crates/nono`, Plan 05); policy decision is centralized in nono-cli
(this module) for the two sites inside the nono-cli crate (`launch.rs` direct spawn,
`agent_daemon/launch.rs`); the broker, as a separate binary, receives its required-outcome as an
explicit parameter over an environment variable this module defines and documents, and performs its
own local probe-then-decide using the same `crates/nono` primitives — never duplicating the
registry or the HMAC-chained event emission into the broker binary. **This function is never called
with `EntryPath::Broker`** — rows expected only at that entry path (`AppContainerProfile` on the
broker arms, per Plan 01's Blocker-1 fix) are attested entirely inside `nono-shell-broker` (Plan 11)
and reach it only through this module's `required_layers_for_broker()` helper, not through
`attest_and_decide` itself.
Output: `crates/nono-cli/src/exec_strategy_windows/attestation.rs` (new).
</objective>

| `NONO_BROKER_REQUIRED_LAYERS` env var, nono-cli → nono-shell-broker | Process-boundary policy hand-off; the broker trusts this value from its own parent, which is the same trust relationship the broker already has for every other spawn parameter |
