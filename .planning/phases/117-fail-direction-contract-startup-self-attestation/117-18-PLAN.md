The `RestrictedToken`/`JobObjectContainment` manual-verification reasoning was specifically about
the EXTERNAL SUBPROCESS harness stalling on teardown AFTER the Supervised event-loop starts — but
both rows ALSO have a direct, in-process unit test calling the underlying guarded function directly
(`create_restricted_token_with_sid`, `apply_process_handle_to_containment`), with no subprocess
spawn at all, so the harness-fragility reasoning does not apply to these tests. Likewise
`DaclAncestorTraverse`/`DaclAncestorReadAttrs`'s manual-verification reasoning was about the SHARED
`DACL_GRANT_FORCE_UNAVAILABLE` flag making them unreachable via the ONE external subprocess test —
but their own in-crate unit tests call each guard's `snapshot_and_apply` directly and are
unaffected. `WfpEgressFilters`'s and `AppContainerProfile`'s manual reasoning was about needing a
live elevated service / real console — but both already have tests that either fabricate the real
guard TYPE with a representable negative value (WFP) or call the crate's own `run()` entry point
in-process (AppContainer), neither of which needs the live infrastructure the manual note describes.

This plan does NOT invent new tests for these 8 rows (7 pre-exist; 1 lands in Plan 117-16, a
sibling wave-6 plan this plan depends on) — it broadens the meta-test's discovery so they are
COUNTED, and updates `MANUALLY_VERIFIED` down to the 3 rows that remain genuinely un-automatable on
an ordinary host: `DaclSessionSidGrant` (structurally empty — no shipped call site applies it, so
there is nothing to force unavailable), `MinifilterAbsence` (structurally absent — no driver
exists), `BrokerAuthenticodeTrustGate` (gated behind `is_dev_build_layout()`, inert outside a
signed production install).

Purpose: satisfy CINT-03's literal bar ("a contract entry with no such test is not satisfied") for
every row that genuinely CAN be satisfied, per the operator's decision, rather than accepting a
weaker discovery mechanism's blind spot as if it were the ground truth.
Output: `layer_registry_meta_test.rs`'s discovery counts 10 of 13 rows as automated (2 pre-existing
subprocess tests + 8 broadened-discovery tests), 3 rows remain `MANUALLY_VERIFIED` with unchanged,
already-accurate reasons; the CI job actually runs the suites that prove this.
