<objective>
Wire the D-21 attestation gate into the two spawn sites that live inside the `nono-cli` crate:
`launch.rs`'s direct `spawn_windows_child` (which also covers the hook path, which re-enters this
same code with no site of its own, and the `BrokerLaunch`/`BrokerLaunchNoPty` arm up to the point
where it hands off to the broker's own child) and `agent_daemon/launch.rs`'s independent daemon
implementation. Both call the same `attest_and_decide()` from Plan 08. This plan also sets the
`NONO_BROKER_REQUIRED_LAYERS` env var when spawning the broker, fixes the factually-wrong
"reverse-of-declaration" drop-order comment (SC4-2), and threads `session_id` plus a computed
dedup key into Plan 09's banner so its per-session dedup is actually exercised, not merely built.

Purpose: this is the literal mechanism that stops nono from ever resuming a child under an
unconfirmed confinement claim on the two entry paths this crate directly controls.
Output: one gate insertion in `launch.rs`, a small signature change in `mod.rs`'s two call sites,
one gate insertion in `agent_daemon/launch.rs`, one comment fix.
</objective>

   private field `_network_enforcement: Option<NetworkEnforcementGuard>` was populated by
   `prepare_network_enforcement` (`mod.rs:484`), which is where the pre-spawn
   `assert_wfp_activation_installed_filters` check (`network.rs:1730`) already ran. Add a new
   parameter to `spawn_windows_child`'s signature: `network_enforcement:
   Option<&NetworkEnforcementGuard>`. Both call sites in `mod.rs` (same module, so `prepared`'s
   private field is directly readable) pass `prepared._network_enforcement.as_ref()`. Inside
   `spawn_windows_child`, derive `let wfp_preconfirmed =

   `FirewallRulesEgress` row and the `None` case (no network restriction requested) both correctly
   fall through to `wfp_preconfirmed = false`, which `attest_and_decide` only escalates to `Abort`
   when the `WfpEgressFilters` row is actually `expected: true` for the current arm (it is not, on
   an unrestricted-network session — `NotApplicable`, not `Unconfirmed`, per Plan 08's dispatch).

2. **Telemetry layer access.** `crate::telemetry::SECURITY_LAYER` is a `pub(crate)
   OnceLock<SecurityEventLayer>` (`telemetry/mod.rs:48`) already accessed the identical way from
   `execution_runtime.rs:267` (`crate::telemetry::SECURITY_LAYER.get().ok_or_else(|| NonoError::
   SandboxInit("... SecurityEventLayer not initialized (AUD-04)".to_string()))?`). `launch.rs` and
   `agent_daemon/launch.rs` are both inside the `nono-cli` crate, so this same
   `crate::telemetry::SECURITY_LAYER.get()` access works unchanged from either file — no parameter
   threading is needed, and none should be added.

**Item-2 fix (checker pass 3, 2026-08-09) — session_id/dedup_key plumbing into the banner call.**
`spawn_windows_child`'s signature already carries `_session_id: Option<&str>` (leading underscore —

names.join(",");` — sorted so the same SET of downgraded layers produces the same key regardless of
iteration order.
