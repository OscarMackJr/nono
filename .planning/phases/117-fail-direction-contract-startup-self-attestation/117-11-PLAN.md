<objective>
Close the last of the three D-21 gate insertion sites: `nono-shell-broker`'s own suspended-spawn
window for the real Low-IL/AppContainer child. This is the site RESEARCH finding 2 identifies as
the one nono-cli's own gate (Plan 10) structurally cannot see — the broker spawns this child inside
its own process, after nono-cli's spawn call has already returned control to the broker binary. It
is also, per Plan 01/08's Blocker-1 fix, the ONLY site that genuinely attests `AppContainerProfile`
on the broker arms — nono-cli's own `attest_and_decide` deliberately never probes this layer.

Purpose: without this plan, the broker arm (`BrokerLaunch`/`BrokerLaunchNoPty`, the fork's actual
production PTY/interactive shape) has a real gap between "nono-cli believes the session is
confined" and "the OS actually confined the process the user's commands run in." The broker already
has a fail-closed label-apply gate at this exact spot (`main.rs:610-661`) — this plan extends it,
it does not invent a new control-flow shape.
Output: a probe-then-decide check inserted before the broker's existing `ResumeThread` call.
</objective>

Every failure branch already follows fail-closed `TerminateProcess` + typed `Err` — this plan's new
check goes immediately before the `ResumeThread(child_thread.raw())` call, inside the same
`if is_app_container` block (the broker's suspended child only exists on the AppContainer path;
there is no separate non-AppContainer suspended-spawn window in this file to also gate).

`crates/nono/src/attestation.rs` (Plan 05): `probe_app_container_sid(process: ProcessHandle) ->
Result<Option<String>>`, `probe_in_job(process: ProcessHandle) -> Result<bool>` — this crate is
already a direct dependency of `nono-shell-broker` (`Cargo.toml:20`). `ProcessHandle` is `HANDLE` on
Windows (a zero-cost alias, Plan 05's Warning-6 fix) — pass `child_process.raw()` unchanged.

`attestation::BROKER_REQUIRED_LAYERS_ENV_VAR` (Plan 08, string constant
`"NONO_BROKER_REQUIRED_LAYERS"`) — this plan reads the env var by its literal string value (the
broker binary does not import `nono-cli`'s `exec_strategy_windows::attestation` module — it is a
separate crate — so hardcode the literal string `"NONO_BROKER_REQUIRED_LAYERS"` here and add a
comment cross-referencing the constant's definition site so the two never silently diverge).

**Warning-10 fix (checker pass 2, 2026-08-09): CLAUDE.md's env-var save/restore rule applies to
this plan's own test, not just to production code.** Tests that mutate `NONO_BROKER_REQUIRED_LAYERS`
via `std::env::set_var` must save the prior value (if any) and restore it in every exit path
(including on panic — use a `Drop`-based guard or an explicit `finally`-shaped block), matching the
project's standing discipline for `HOME`/`TMPDIR`/`XDG_CONFIG_HOME` in-process test mutation.
`--test-threads=1` reduces but does not eliminate cross-test leakage risk in the same process when
save/restore is skipped.
