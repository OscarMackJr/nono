**Warning-8 fix (checker pass 2, 2026-08-09): a downgrade nobody reads is the honesty gap
reappearing one level up.** The original design gave `print_attestation_downgrade_banner` a
`silent: bool` parameter that suppressed the line entirely — meaning `--silent` could mute the one
channel a human actually reads while the session proceeds under a downgraded claim. **Decision:**
the downgrade banner is exempt from `--silent`. `--silent` suppresses routine/informational output
(the version banner, capability summaries); it must NOT suppress a security-relevant notice that a
confinement guarantee was not fully confirmed.

**Item-2 fix (checker pass 3, 2026-08-09) — per-session dedup, not per-spawn.**
`claude_code_hook.rs` re-enters the direct spawn path on every tool call — a fresh `nono.exe`
process each time (confirmed by RESEARCH: the hook rewrites `Bash` calls into a `nono run`
invocation string). On a host where a row persistently sits non-`Confirmed` (D-18's own accepted
tension names WFP as the candidate), an un-deduplicated banner fires on every single tool
invocation. **Decision:** dedup per session (across the multiple process spawns one Claude Code
session produces), not per spawn — the first occurrence of a given downgraded-layer-set always
prints; only an identical repeat within the same `session_id` is suppressed. **No new silence
switch is introduced** — this is a content-addressed, per-session "already announced" marker, not a
verbosity flag. Concrete mechanism: `spawn_windows_child` (`launch.rs:1346-1354`) already receives
`_session_id: Option<&str>` (currently unused — Plan 10 drops the underscore and threads it
through). The dedup marker lives under the existing per-session directory convention
(`crates/nono-cli/src/state_paths.rs::sessions_dir()`, the same root `ensure_audit_session_dir`
uses for audit sessions, `crates/nono-cli/src/audit_session.rs:46`) —
`sessions_dir()?.join(session_id).join("attestation-downgrade").join(<hex of a std::hash::DefaultHasher
over the sorted, comma-joined LayerId Debug-names>)` as a zero-byte marker file. This dedup logic is
**best-effort and non-fatal**: any I/O failure (directory creation, marker read/write) defaults to
"not yet announced" — i.e. it prints — since erring toward MORE visibility, never less, is the only
direction that preserves the D-27 no-silent-downgrade property; a dedup-marker write failure must
never become a printed-then-silently-repeated banner, and it must never itself abort the launch (log
via `tracing::debug!`, nothing louder, and continue). `output.rs` itself does the dedup check/write
— it does NOT need to import `LayerId` to do so: the caller (which already has `LayerId` in scope)
computes the sorted, comma-joined dedup key string and passes it in as a plain `&str`; the acceptance
criterion "`grep -c "LayerId" crates/nono-cli/src/output.rs` returns 0" (Task 2, unchanged from the
prior pass) still holds.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| supervisor console (stderr) — potentially shared with the confined child in supervised/PTY arms | The banner is the one channel whose child-readability cannot be proven safe per-arm in this phase, hence the coarse-on-every-arm default |
| ETW / Application Event Log | Written only by the supervisor's own `windows::emit_security_event` call; assumed (not yet empirically verified) unreadable by a Low-IL/AppContainer child — Plan 12 Task 2 adds the concrete verification step |
| per-session dedup marker file (`sessions_dir()/<id>/attestation-downgrade/<hash>`) | Written by the supervisor only; a compromised confined child writing/deleting this file could at most cause a REPEAT banner (delete) or a suppressed repeat within the SAME set (write) — it can never suppress the first occurrence, since the dedup check only ever affects whether a REPEAT prints |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-117-04 | Information Disclosure | banner reconnaissance | mitigate | Banner text is mechanically verified layer-name-free (Task 2 acceptance criteria: `grep -c "LayerId"` returns 0) and identical on every arm — no per-arm branch that could leak which specific layer is degraded to a console the child might share; `dedup_key` is opaque and only ever hashed, never displayed |
| T-117-17 | Information Disclosure | ETW/AppLog readability by a confined child (unverified) | accept-with-followup | The specific-layer-name field is added to the telemetry event on the documented assumption that ETW/Application Event Log is supervisor-only; this assumption is NOT yet empirically verified — Plan 12 Task 2 adds a concrete, loud, named manual-verification item (`wevtutil gl Application` SDDL inspection) rather than a bare mention (Blocker-3 fix, checker pass 2) |
| T-117-22 | Repudiation | a downgrade nobody reads (`--silent` muting the only human-visible channel) | mitigate | `print_attestation_downgrade_banner` (Task 2) takes no `silent` parameter and prints unconditionally whenever `downgraded_count > 0` (subject only to the per-session dedup, which affects repeats, never the first occurrence) — the honesty-gap-one-level-up failure mode Warning-8 identified is closed by removing the suppression path entirely |
| T-117-25 | Denial of Service | per-session dedup marker I/O failure suppressing a first-occurrence banner | mitigate | The dedup check only ever runs AFTER the print already happened (Task 2: print first, then best-effort mark) — a marker-write failure can only cause an extra repeat print next time, never a suppressed first occurrence; marker I/O errors are logged via `tracing::debug!` and never propagated as fatal |
| T-117-SC | Tampering | supply chain | accept | No new crate dependencies added; the dedup hash uses `std::hash::DefaultHasher` |
</threat_model>
