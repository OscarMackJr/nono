<objective>
Establish the TRUE `cargo test --workspace --no-fail-fast` baseline for this codebase, on HEAD,
before any round-4 code fix lands. The orchestrator's own investigation found that
`cargo test --workspace` (no `--no-fail-fast`) is fail-fast ACROSS targets — `--bin nono` runs
first, hits the 11 documented pre-existing Windows-host failures, and cargo stops without ever
building or running any `tests/*.rs` integration binary. Six review iterations, eight executor
self-checks, and the orchestrator's own prior passes all reported "matches baseline" while never
executing the integration targets this way. `cargo test --workspace --no-fail-fast` on the same
tree reports `error: 6 targets failed` — CR-04 (the round's own SPEC drift gate failing on HEAD)
was invisible for exactly this reason, having shipped through 117-32's plan, 117-34's dependent
plan, and 117-34's own `cargo test --workspace` verify without ever running.

This plan runs FIRST in the round, before any other round-4 plan touches source, so the captured
baseline reflects the pre-round-4 state exactly — a mixture of long-documented pre-existing
failures (the 11 `nono`-binary Windows HOME/env-race failures, WR-20's host-blocked test = 12;
`resl_nix_async_signal_safety::cr_01_no_format_macro_in_post_fork_child_branch`, red since ~Phase
25) and CR-04's genuine regression (`layer_registry_selfcheck::
every_spec_symbol_citation_resolves_to_a_real_definition`). Every later plan in this round
(117-36 through 117-45) depends on this plan so no fix plan runs before the true baseline is on
record, and every later plan's suite-level `<verify>` block uses `--no-fail-fast`.

Purpose: stop grading this phase's test suite against a command that structurally cannot see most
of it, and hand every subsequent plan in this round a concrete, dated, complete list of what is
and is not this round's responsibility.
