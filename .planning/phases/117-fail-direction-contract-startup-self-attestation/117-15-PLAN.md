<objective>
Close NR3-03 and NR3-08 together — both are correctness defects in the SAME file
(`layer_registry.rs`), one in its doc comments/citations and one in its test coverage of its own
fail-open landmine.

**NR3-03:** `layer_registry.rs`'s `DACL_SESSION_SID_GRANT_EXPECTANCY` doc comment states that
`dacl_session_sid_grant_is_not_claimed_anywhere` "fails the build if anyone re-adds an expectancy
cell without also making the grant real." That test does not exist anywhere in the tree (`grep -rn`
returns exactly the doc comment itself). `DaclSessionSidGrant`'s row is hardcoded `NotApplicable` in
`AppliedLayers::status()`; if its expectancy is ever restored (RF-03 names this as an explicitly
OPEN operator decision, not resolved here), the row silently drops out of every decision — a
fail-open in the module whose entire purpose is truthful layer accounting.

**NR3-08:** Registry call-site citations for four rows (`MandatoryIntegrityLabel`,
`DaclPackageSidGrant`, `DaclAncestorTraverse`, `DaclAncestorReadAttrs`) drifted ~145 lines in the
iteration-2 fix pass — this is the THIRD consecutive review pass this has been deferred across.
NR3-08's own recommendation is symbol citations instead of re-running line numbers, which stops the
drift recurring rather than merely correcting it once more.

Purpose: close the fail-open landmine on the row the reviewer called "the single most concerning
finding in this verification pass" (per VERIFICATION.md), and end the citation-drift class
permanently rather than for one more cycle.
Output: two new discovery-based tests pinning the `DaclSessionSidGrant` invariant in both
directions; symbol-form call-site citations for the four drifted rows; the selfcheck test extended
to verify symbol citations by content.
</objective>
