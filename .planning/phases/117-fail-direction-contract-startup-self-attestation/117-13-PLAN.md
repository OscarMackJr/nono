<objective>
Close NR3-01 — the one open BLOCKER from `117-REVIEW.md` iteration 3. CR-14's fix
(`labels_guard.rs`) made `applied == 0` on a non-empty policy a hard `Abort`. That is correct for
a genuine zero-coverage launch, but `applied == 0` is also nono's own steady-state residue: any
path that already carries a mandatory-label ACE — including one nono itself wrote on a PRIOR
launch that never reached `Drop` (Ctrl-C, kill, crash) — records `SkipPreExistingLabel`, so the
NEXT launch of the same workspace (or the second of two concurrent sessions) sees `applied == 0`
and hard-aborts with no remediation and no recovery path. This plan makes that residue
self-healing (a prior label matching THIS launch's own mode-derived mask is recognized as already
covered, not skipped) and gives the operator a typed, structured remediation for the case that
still fails.

Purpose: nono must never lock itself out of its own workspace after its own abnormal exit — that
is an availability regression the phase's own fix introduced, and it directly undermines CINT-02
("nono never proceeds while presenting a confinement guarantee it cannot substantiate" implies it
also must not spuriously refuse a guarantee it CAN substantiate).
Output: self-healing residue detection in `AppliedLabelsGuard`, a typed `NonoRemediation` variant,
and a `NonoError::remediation()` arm wired to it — all covered by tests that assert BOTH
directions (residue recovers; a real zero-coverage launch still aborts).
</objective>
