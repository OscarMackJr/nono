<objective>
Close WR-29 — D-37's widened `NotApplicable` arm silently defeats the D-26 tighten-only mechanism.
`decide_from_entries` short-circuits on `status == LayerAttestationStatus::NotApplicable ||
(Confirmed && !partially_established)` with a bare `continue` BEFORE it ever consults
`required_names` (the D-26-tightened set). Before Plan 117-28 (D-37), a walk that stopped at the
first non-owned ancestor classified `PartiallyApplied` -> `EstablishedNotIndependentlyObservable` +
`partially_established` -> reached the tighten check -> `Abort` if tightened. After D-37 it
classifies `NotApplicable` -> the `continue` fires before `tightened` is even read -> an operator
(or an `HKLM\...\RequiredLayers` fleet policy, once RF-13's open enforcement decision lands) that
explicitly REQUIRES `DaclAncestorTraverse` gets a silent Proceed instead of an Abort. The SPEC's
RF-16 paragraph ("a D-26-tightened requirement on a partially established layer still aborts") is
now false for this specific condition. Currently latent only because `apply_startup_attestation_
gate` hardcodes `required_layers_override: &[]` / `machine_required_layers: &[]` — it becomes live
the moment that wiring lands. Fail-secure is non-negotiable in this codebase (CLAUDE.md); treat
this as fail-open until fixed, even though it is filed as a warning, not a blocker.

Purpose: make D-26 tightening observe EVERY non-Confirmed status, including the D-37 NotApplicable
case, closing a fail-open path that a future (already-planned) wiring change would otherwise
silently activate.
Output: `decide_from_entries` evaluates `tightened` before any `NotApplicable`/`Confirmed`
short-circuit; a new test proves a tightened NotApplicable row aborts.
</objective>
